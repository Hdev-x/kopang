# 화면 완료와 검증 기준

> 상태: 팀 합의 전 체크리스트

## 모든 화면 공통

- [ ] API success 데이터를 표시한다.
- [ ] loading 상태가 있다.
- [ ] empty 상태가 있다.
- [ ] error 상태와 재시도 또는 다음 행동이 있다.
- [ ] 긴 제목·가격·이름에서 layout이 깨지지 않는다.
- [ ] 버튼과 링크의 역할이 구분된다.
- [ ] disabled 상태가 시각과 기능 모두 적용된다.
- [ ] keyboard focus를 확인한다.
- [ ] 이미지 실패 시 대체 표현이 있다.
- [ ] console error가 없다.

## Mobile 검증

- [ ] 360px
- [ ] 390px
- [ ] 작은 화면에서 가로 overflow가 없다.
- [ ] tap target이 충분하다.
- [ ] fixed header/footer가 콘텐츠를 가리지 않는다.
- [ ] hover 없이 모든 기능을 사용할 수 있다.
- [ ] 긴 세로 scroll에서 주요 CTA에 접근 가능하다.

## Web 검증

- [ ] 팀이 정한 기준 desktop 너비
- [ ] content max-width 이상에서 정렬이 유지된다.
- [ ] grid column과 gutter가 화면마다 일치한다.
- [ ] hover와 focus-visible 상태가 있다.
- [ ] keyboard tab 순서가 자연스럽다.
- [ ] 넓은 공간을 단순 확대가 아니라 정보 구조 개선에 사용한다.
- [ ] mobile 기기에서 PC 보기를 선택해도 desktop layout을 유지한다.

## Admin 검증

- [ ] KPI 숫자와 단위가 명확하다.
- [ ] filter 조건과 초기화가 보인다.
- [ ] table header와 데이터 정렬이 일치한다.
- [ ] churn 위험도 색만으로 의미를 전달하지 않는다.
- [ ] chart에 label 또는 legend가 있다.
- [ ] 권한 없음과 데이터 없음이 구분된다.
- [ ] destructive action에 확인 단계가 있다.

## Route 전환 검증

- [ ] `/mobile/products/:id`에서 같은 상품의 `/web/products/:id`로 이동한다.
- [ ] web에서 mobile로 돌아갈 수 있다.
- [ ] 사용자의 선택이 새로고침 후 유지된다.
- [ ] 로그인 상태가 전환 후 유지된다.
- [ ] 장바구니 상태가 전환 후 유지된다.
- [ ] 대응하지 않는 route의 fallback이 있다.
- [ ] `/admin/*`에는 보기 전환이 적용되지 않는다.

## 자동 검증

```text
npm run build
npm run lint
```

자동 검증 후 실제 브라우저에서 각 기준 너비와 interaction을 확인한다.

## PR 완료 조건

- [ ] 작업 영역이 mobile/web/admin 중 명확하다.
- [ ] 다른 영역의 파일을 불필요하게 수정하지 않았다.
- [ ] 새 token/component를 추가한 이유가 PR에 적혀 있다.
- [ ] 정상·loading·empty·error 스크린샷이 있다.
- [ ] build·lint 결과가 기록됐다.
- [ ] 관련 디자인 링크가 연결됐다.
