## 4. 결정 로그

결정은 기존 내용을 지우지 않고 아래 형식으로 누적한다.

### 2026-07-22 — Web 대표 화면과 QuickBar 1차 방향

- 결정: Web Home·Category·ProductDetail의 1차 레퍼런스를 오늘의집으로 정한다.
- 결정: 화면 오른쪽에 장바구니·최근 본 상품·도움말·맨 위로 기능을 가진 QuickBar를 둔다.
- 결정: 장바구니와 최근 본 상품은 페이지 이동 없이 중앙 Modal로 먼저 검증한다.
- 이유: 사용자가 실제 화면을 보며 크기·위치·정보량을 결정하기 위해 먼저 단순한 뼈대를 만든다.
- 대안: 목록이 길거나 원래 페이지와 비교하기 어렵다면 오른쪽 Drawer로 교체한다.
- 적용 영역: Web 사용자 화면
- 영향 파일: `src/web`, `src/routes/AppRouter.tsx`, `src/styles/tokens.css`
- 참여자: 사용자, AI
- 다시 검토할 조건: Modal이 원래 콘텐츠를 과도하게 가리거나 QuickBar와 열린 패널의 위치 관계가 어색할 때

```text
### YYYY-MM-DD — 결정 제목

- 결정:
- 이유:
- 적용 영역:
- 영향 파일:
- 참여자:
- 다시 검토할 조건:
```

## 5. 디자인 전달 시 함께 받을 정보

- 원본 링크와 정확한 frame/node
- 적용 대상: mobile/web/admin
- 기준 viewport
- 사용한 font와 icon
- component와 variant
- hover/pressed/disabled/loading 상태
- 화면 전환 또는 modal 동작
- image/SVG asset
- 미확정 영역

## 6. 디자인을 코드로 옮길 때 확인

- 디자인 값이 기존 token에 있는가?
- 없으면 공통 token인지 영역 전용 token인지?
- 기존 component로 표현 가능한가?
- 별도 component가 필요한 만큼 DOM·interaction이 다른가?
- 정상 화면 외 loading·empty·error가 정의됐는가?
- API 응답으로 표시할 실제 field가 명확한가?
