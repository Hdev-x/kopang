# 디자인 링크·담당·결정 기록

> 상태: 팀원이 링크를 전달하면 채우는 협업 문서

## 1. 디자인 원본

| 구분 | 링크 | 담당자 | 상태 | 마지막 확인 |
|---|---|---|---|---|
| 공통 Foundation | 미입력 | 미정 | 대기 | - |
| Mobile Home | 미입력 | 미정 | 대기 | - |
| Web Home | 미입력 | 미정 | 대기 | - |
| Mobile Product | 미입력 | 미정 | 대기 | - |
| Web Product | 미입력 | 미정 | 대기 | - |
| Admin Churn | 미입력 | 미정 | 대기 | - |

링크는 가능하면 file 전체보다 확정 frame 또는 page 링크를 기록한다.

## 2. 담당 경계

| 영역 | 담당자 | 포함 화면 | 공통 파일 수정 권한 |
|---|---|---|---|
| Mobile | 미정 | 기존 사용자 화면 | 협의 필요 |
| Web | 미정 | PC 사용자 화면 | 협의 필요 |
| Admin Churn | 사용자 | 이탈방지 dashboard·알림 | 협의 필요 |
| 공통 Foundation | 미정 | token·primitive component | 최종 수정자 필요 |

## 3. 결정해야 할 항목

- [ ] URL: `/mobile`, `/web`
- [ ] 기존 `/`의 기본 이동
- [ ] 최초 기기 감지 기준
- [ ] 수동 선택 저장 방식
- [ ] Mobile 기준 390px·최소 360px
- [ ] Web 기준 너비·content max-width
- [ ] 공통 color·font·icon·radius
- [ ] Mobile typography·spacing
- [ ] Web typography·grid
- [ ] Admin table·KPI·chart 규칙
- [ ] 공통 component 최종 수정자
- [ ] 대표 검증 화면과 마감

## 4. 결정 로그

결정은 기존 내용을 지우지 않고 아래 형식으로 누적한다.

```text
### YYYY-MM-DD — 결정 제목

- 결정:
- 이유:
- 적용 영역:
- 영향 파일:
- 참여자:
- 다시 검토할 조건:
```

## 5. 디자인 전달 시 함께 받을 정보

- 원본 링크와 정확한 frame/node
- 적용 대상: mobile/web/admin
- 기준 viewport
- 사용한 font와 icon
- component와 variant
- hover/pressed/disabled/loading 상태
- 화면 전환 또는 modal 동작
- image/SVG asset
- 미확정 영역

## 6. 디자인을 코드로 옮길 때 확인

- 디자인 값이 기존 token에 있는가?
- 없으면 공통 token인지 영역 전용 token인지?
- 기존 component로 표현 가능한가?
- 별도 component가 필요한 만큼 DOM·interaction이 다른가?
- 정상 화면 외 loading·empty·error가 정의됐는가?
- API 응답으로 표시할 실제 field가 명확한가?
