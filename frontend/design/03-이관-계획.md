# 기존 Mobile 보존과 단계별 이관 계획

> 상태: 실행 전 제안안

## 원칙

- 초기 이관은 파일 경계 정리가 목적이다.
- 기존 mobile 화면의 JSX·CSS·기능을 동시에 재설계하지 않는다.
- 이동과 디자인 변경을 같은 PR에 섞지 않는다.
- 최신 `develop`을 반영하고 팀원의 진행 branch를 확인한 후 시작한다.
- 대량 이동 전에 대표 화면으로 구조를 검증한다.

## 0단계: 팀 합의

- [ ] `/mobile`, `/web` 경로 승인
- [ ] 기존 화면을 mobile 기준으로 인정
- [ ] admin 독립 유지 승인
- [ ] 본인·팀원 화면 담당 확정
- [ ] 공통 파일 최종 수정자 확정
- [ ] 진행 중인 frontend branch와 겹치는 파일 확인

## 1단계: 이동 없는 뼈대 검증

기존 파일은 유지하고 web만 추가한다.

```text
src/
├─ pages/             # 기존 mobile 화면 유지
├─ components/        # 기존 component 유지
├─ web/               # 신규
│  ├─ pages/
│  ├─ components/
│  └─ styles/
└─ routes/
```

- [ ] `WebLayout` 생성
- [ ] `WebHomePage` 생성
- [ ] 임시 `/web` route 연결
- [ ] 기존 `/` 화면에 시각·기능 회귀가 없는지 확인

## 2단계: Router 분리

- [ ] `MobileRoutes`에서 기존 사용자 페이지를 연결
- [ ] `WebRoutes`에서 신규 web 페이지를 연결
- [ ] `AdminRoutes`에서 기존 관리자 페이지를 연결
- [ ] 같은 세부 경로를 유지하는 보기 전환 규칙 추가
- [ ] 사용자가 선택한 모드 저장
- [ ] 저장값이 없을 때만 최초 기기 감지

## 3단계: 대표 화면 검증

전체 페이지를 옮기기 전에 아래 3개를 검증한다.

1. Home: navigation, section, product card
2. ProductDetail: 정보 구조, CTA, modal
3. Cart: 선택, 합계, empty/error 상태

- [ ] mobile 기존 화면 유지
- [ ] web 별도 UI 제작
- [ ] API와 type 공유
- [ ] 공통 Foundation 적용
- [ ] URL 전환 시 동일 페이지 유지

## 4단계: 기존 파일을 mobile 경계로 이동

대표 화면과 Router가 안정된 뒤 실행한다.

```text
src/pages/product/HomePage.tsx
→ src/mobile/pages/product/HomePage.tsx
```

이 단계에서는:

- 파일 위치와 import만 변경한다.
- CSS selector와 JSX는 변경하지 않는다.
- API endpoint와 응답 처리를 변경하지 않는다.
- rename/move PR과 디자인 수정 PR을 분리한다.

공통 여부를 먼저 분류한다.

| 현재 항목 | 초기 분류 제안 |
|---|---|
| `api/` | shared |
| `types/` | shared |
| `hooks/` | shared 검토 |
| `lib/` | shared 검토 |
| `Layout` | mobile |
| `ProductCard` | mobile 우선 |
| `Button` | shared 후보 |
| `Input` | shared 후보 |
| `AdminLayout` | admin |
| `pages/admin` | admin |

## 5단계: 화면 단위 확장

한 PR에 한 화면 흐름을 권장한다.

```text
Home
→ ProductList
→ ProductDetail
→ Cart
→ Checkout
→ Order
→ My
→ Auth
```

각 단계에서 build·lint·브라우저 검증 후 다음 화면으로 이동한다.

## Rollback 기준

다음 상황이면 전체 이관을 중단하고 대표 화면 단계로 돌아간다.

- 공통 component 조건문이 계속 증가함
- 팀원 branch와 대량 충돌 발생
- mobile 기존 기능 회귀 발생
- 같은 API 로직이 두 영역에 복제됨
- 담당자가 구조를 설명하기 어려움
