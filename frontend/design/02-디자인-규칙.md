# 공통·Mobile·Web·Admin 디자인 규칙

> 상태: 값 확정 전 계약 초안

## 1. 규칙 계층

```text
공통 Foundation
├─ Mobile 규칙
├─ Web 규칙
└─ Admin 규칙
```

공통 Foundation은 같은 브랜드라는 인상을 만든다. 영역별 규칙은 각 사용 환경에 맞는 크기·배치·동작을 정한다.

## 2. 전 영역 공통 Foundation

### Color

- brand primary와 상태별 primary
- page background, surface, border
- primary/secondary/disabled text
- success, warning, danger, info
- sale, churn risk처럼 제품 의미가 있는 semantic color
- 동일 의미에 다른 색을 임의로 사용하지 않는다.

### Typography

- font family
- 사용 가능한 font weight
- 숫자·금액 표시 방식
- title/body/caption의 의미
- line-height 기본 원칙

영역별 font size는 달라도 의미 계층은 유지한다.

### Shape와 시각 언어

- radius scale
- shadow/elevation 단계
- border 기본 굵기
- icon library와 stroke 스타일
- logo 사용법

### 상태 의미

- loading
- empty
- error
- success
- disabled
- selected
- destructive action

상태의 모양은 달라도 같은 상태가 전달하는 의미와 색은 일치해야 한다.

## 6. Token 구조 제안

```css
/* 공통 Foundation */
--color-brand-primary;
--color-text-primary;
--color-text-secondary;
--color-success;
--color-warning;
--color-danger;
--font-family-base;
--radius-sm;
--radius-md;
--space-base;

/* Mobile */
--mobile-page-padding;
--mobile-header-height;
--mobile-touch-height;
--mobile-body-size;

/* Web */
--web-content-max-width;
--web-grid-gap;
--web-header-height;
--web-body-size;

/* Admin */
--admin-content-max-width;
--admin-nav-width;
--admin-table-row-height;
--admin-kpi-gap;
```

현재 `tokens.css`의 이름을 바로 바꾸지 않는다. 대표 화면에서 새 계층을 검증한 후 호환성을 유지하며 단계적으로 추가한다.

## 7. 공통 Component 계약

공통 후보:

- Button
- Input
- Badge
- Spinner
- Toast
- 기본 Icon wrapper

각 component에는 필요한 variant와 state를 먼저 문서화한다.

예:

```text
Button
├─ variant: primary | secondary | ghost | danger
├─ size: mobile | web 또는 sm | md | lg
└─ state: default | hover | pressed | disabled | loading
```

페이지가 임의 variant를 추가하지 않는다. 새 variant가 필요하면 공통 소유자 검토 후 추가한다.

## 9. 바이브코딩 요청 규칙

AI 요청에는 다음을 포함한다.

```text
- frontend/design과 DESIGN_SYSTEM.md의 규칙을 따른다.
- 작업 영역은 mobile/web/admin 중 하나로 제한한다.
- 공통 Foundation token을 사용한다.
- 해당 영역의 layout·typography·interaction 규칙을 사용한다.
- 다른 영역의 파일을 수정하지 않는다.
- loading·empty·error·data 상태를 함께 구현한다.
- 새 공통 component나 token이 필요하면 먼저 제안한다.
```
