## 0. 확정된 전제
- **백엔드 ORM**: MyBatis (확정)
- **DB**: PostgreSQL
- **프론트**: React (담당: 본인)
- **인증**: Spring Security + JWT — **수업에서 코드+트러블슈팅까지 다룸** (6월 전반기 노트)
  → 배운 방식 그대로 가는 게 안전. 레퍼런스·지뢰밭 지도가 이미 있음
- **팀 상황**: 전반적으로 초급 → "기한 내 동작" vs "실무 표준 학습" 우선순위 합의 필요

## 1. 역할 경계 (먼저 합의할 것)

| 구분 | 결정 주체 | 비고 |
|---|---|---|
| 백엔드 내부 구현 (인증 방식, 로그인 위치 등) | **백엔드 담당** | 만드는 사람이 난이도·일정 책임 |
| **API 명세서(계약)** | **공동 결정** | 프론트 코드가 직접 의존 → 위임 불가 |

## 2. 결정해야 할 기술 항목

### 2-1. HTTP 통신 라이브러리 (프론트) — ✅ axios 제안
| | fetch | axios |
|---|---|---|
| 실무 점유율 | 낮음 | **높음** |
| 인터셉터(토큰 자동주입) | 직접 구현 | **내장** |
| JSON 파싱 / 에러 처리 | 수동 | 자동 |

- **프론트 제안: axios** (인터셉터 편의 + 실무 표준)
- ⚠️ **인터셉터는 수업에서 안 다룸(심화)** → 자습 필요. 아래 "수업에서 안 다룬 것" 참고
- 보완: 개발자도구 Network 탭으로 실제 요청 status/header 관찰하며 원리 학습

### 2-2. 인증 처리 방식 (백엔드) — ✅ 확정: Spring Security 필터
- **수업에서 Security 필터 방식을 배움** → 이걸로 확정.
  Interceptor가 이론상 단순해도, 배운 것(레퍼런스+트러블슈팅 보유)이 초급 팀엔 더 안전.
- ~~Interceptor 먼저 → 나중에 리팩토링~~ : 3주짜리에선 "나중"이 안 옴. 처음부터 Security로.

### 2-3. 로그인 구현 위치 (백엔드) — ✅ 확정: 필터(successfulAuthentication)
- **수업에서 배운 방식 그대로**: `UsernamePasswordAuthenticationFilter` 상속 →
  `/login` 요청 시 `successfulAuthentication`에서 토큰 발급 → JSON 응답
- 주의(수업 트러블슈팅): 토큰 발급 후 `chain.doFilter()` 빠뜨리지 말 것 /
  `AuthenticationManager`는 SecurityConfig에서 수동 주입(`new ...Filter(authManager)`)

### 2-4. 토큰 저장소 (프론트) — ✅ 확정: sessionStorage
| | localStorage | sessionStorage | httpOnly 쿠키 |
|---|---|---|---|
| 난이도 | 쉬움 | 쉬움 | 어려움 |
| 보안(XSS) | 취약 | 취약(탭 닫으면 소멸) | **안전** |

- **수업에서 sessionStorage로 배움** → 이걸로 확정 (익숙 + localStorage보다 살짝 안전)
- **모범답안은** Access=메모리/sessionStorage, Refresh=httpOnly 쿠키지만,
  httpOnly 쿠키는 백엔드 CORS·SameSite까지 얽혀서 3주엔 과함 → 이번엔 sessionStorage로 통일
  - ※ XSS = 악성 스크립트 주입으로 토큰 탈취하는 공격. JS로 읽히는 storage는 취약, httpOnly 쿠키는 JS 접근 불가

---

## 2-5. ✅ 수업 값 그대로 못 박을 설정
- Access Token **15분** / Refresh Token **7일**
- 프론트 저장: **sessionStorage** + 요청 헤더 `Authorization: Bearer <token>`
- CORS: `allowedOrigins = http://localhost:5173`(Vite), `allowCredentials = true`,
  `exposedHeaders = Authorization`, csrf disable, 세션 STATELESS
- JWT 시크릿/DB 정보: `.env` + `.gitignore` (GitHub 노출 방지)
- 권한(role): `USER` / `ADMIN` 두 개만

## ⚠️ 수업에서 안 다룬 것 (별도 시간 확보)
수업 노트에 "심화(Beyond the Class)"로만 언급됨 = 직접 해야 함.

| 항목 | 담당 | 비고 |
|---|---|---|
| **axios 인터셉터** (토큰 자동주입 + 401 시 refresh 재시도) | 프론트 | 자습 필요. 시간 잡기 |
| **401(토큰 만료) 응답 포맷 / 예외 세분화** | 공동 | 인터셉터가 이 포맷에 의존 → 3번 체크리스트 직결 |
| **Refresh 토큰 서버 저장**(Redis/DB) | 백엔드 | 수업은 클라이언트로만 보냄. 3주면 스트레치/생략 가능 |
| **실제 라우트 보호** | 백엔드 | 수업 예제는 `permitAll()`이라 전부 허용. 막을 API 직접 지정 |
